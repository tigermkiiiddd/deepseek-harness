# ACP 能力投影契约 —— DeepSeek Harness 经 ACP 完整自封装（阶段 A）

状态：approved-plan / 施工依据。上游决策记录见 [.opencode/plans/acp-full-self-encapsulation.md](../../.opencode/plans/acp-full-self-encapsulation.md)（批准的架构终稿与阶段划分）；本文件是阶段 B/C/D 的逐能力施工契约。

## 0. 不变量与范围

1. 主实例经 apiproxy 暴露的会话域能力，成员进程经 ACP 后全量具备；不设批次。
2. 桥只做机械投影：每个 `dsh/*` 方法对应成员进程内一个既有服务调用，桥内不出现新业务逻辑。
3. 宿主侧（packages/team）对一切 ACP 对端说同一套协议；界面可用性由 initialize 协商的能力位驱动，不允许按「成员类型」分支。
4. 日志权威在成员进程；历史、搜索、导出等日志类操作经协议路由到属主，宿主不镜像日志。

## 1. 能力协商

`initialize` 结果的 `AgentCapabilities` 增加：

```jsonc
{
  "capabilities": {
    // …原生能力…
    "dsh": {
      "sessions": ["list", "historyPage", "queue", "rerun", "fork", "rename", "state", "compact", "search", "export"],
      "attachments": ["get"],
      "userQuestions": true,
      "providers": true   // 迁移自 unstable_listProviders/unstable_setProvider
    }
  }
}
```

缺失 `dsh` 键 = 第三方最小实现；宿主据此隐藏入口（数据驱动的缺席，不是报错兜底）。`setSessionConfigOption` 沿用 ACP 原生能力位。

## 2. 通用约定

- **命名**：扩展方法一律 `dsh/<域>/<动作>`，JSON-RPC 参数对象单参。现有 `unstable_listProviders` / `unstable_setProvider` 在本次一并迁移为 `dsh/provider/list` / `dsh/provider/set`（两端都是我们的代码，无兼容负担）。
- **会话标识**：全部方法携带成员自己的 topic `sessionId`（string）。宿主持有的 `member:<memberId>:<topicId>` 虚拟 id 仅在宿主↔前端之间存在，永不跨线。
- **错误**：复用 ACP 层既有错误构造（`invalidParams` / `internalError` / 自定义 code）。业务错误码与 apiproxy 现行码对齐：`session-not-found`、`model-unavailable`、`queue-item-not-found`、`attachment-error` 等；第三方 CLI 未实现某方法时返回标准 JSON-RPC `-32601`，宿主按能力位预先隐藏而非依赖该错误。
- **事件**：异步变更经既有 `session/update` 通知通道携带扩展变体（见 §4 state/compaction），不复用 `config_option_update`。

## 3. 逐能力契约

### 3.1 模型目录全量化（改造既有原生面）

- 来源：`ctx.llm` 全部已注册路由（对齐 apiproxy `buildModelCatalog` 的枚举缝），不再限定默认路由。
- 编码：选项 value 由桥生成组合串 `value(provider, model) = \`${provider}/${model}\``；`currentValue` 为当前 selection 的组合串。
- 解码：`changeModel` 对**枚举条目整串匹配**（遍历目录比较生成值），不做字符串切分——模型 id 含 `/` 也无歧义。
- 效果：命中后同时改写 `modelRef.current.provider` 与 `.model`，下一轮请求生效；跨 provider 切换由此获得。
- 广告条件收敛：只要 llm 缝存在且任一路由目录非空即广告；初始 selection 仅决定 currentValue，不再是广告前提。
- 测试锚点：`packages/acp/acp/tests/config-option.spec.ts` 扩展多路由、含斜杠 id、未知组合值拒绝、跨路由切换后 prompt 携带新 provider/model。

### 3.2 会话列表 `dsh/session/list`

- 入参 `{ cwd?: string }`；出参 `{ sessions: [{ sessionId, cwd, title?, updatedAt? }] }`。
- 即现桥 `listSessions` 扩展转正；能力位 `sessions:list`。

### 3.3 历史分页 `dsh/session/historyPage`

- 入参 `{ sessionId, before?: number(seq), limit: number }`；出参 `{ events: AcpUpdate[], nextBefore?: number }`。
- 成员侧实现读自身会话日志窗口；替代现「load 全量回放再截取」的宿主读取路径（team `readHistoryEvents` 改为分页拉取）。
- 上限：`limit` 服务端钳制（复用日志读取既有页大小上限），超界返回钳制值。

### 3.4 排队与 steer `dsh/session/queue`

- 入参 `{ sessionId, action: 'enqueue'|'remove'|'edit'|'steer', item?: { text, images?, at? }, id?, text? }`。
- 成员侧实现直通其进程内 agent-loop 收件箱（主实例同源能力），桥零逻辑。
- 出参 `{ queue: [{ id, text, … }] }`；错误：`queue-item-not-found`。
- steer 语义与主实例一致：回合进行中插入为引导输入。

### 3.5 重发 `dsh/session/rerun`

- 入参 `{ sessionId, at: seq }`；行为=主实例 rerun 语义在成员进程内执行：checkpoint 截断其后日志并以原输入重开回合。
- 出参 `{ accepted: true }`；流式更新照常经 `session/update`。

### 3.6 分叉 `dsh/session/fork`

- 入参 `{ sessionId, at: seq }`；出参 `{ sessionId: 新话题id }`。
- 成员侧用自身 fork 服务；新话题进入 `dsh/session/list` 自然可见。

### 3.7 改名 `dsh/session/rename`

- 入参 `{ sessionId, title }`；出参 `{ title }`。
- 成员侧调 session-title 服务写持久标题；`dsh/session/list` 与后续 load 反映之。

### 3.8 会话状态 `dsh/session/state`（todo / plan / goal）

- 读：入参 `{ sessionId }`；出参 `{ todo?: TodoSnapshot, plan?: PlanSnapshot, goal?: GoalSnapshot }`。
- 变更：`session/update` 通道增加扩展变体 `{ type: 'dsh/state', domain: 'todo'|'plan'|'goal', snapshot }`；反向翻译器折叠进宿主事件流，前端零特判消费。

### 3.9 压缩 `dsh/session/compact`

- 触发：入参 `{ sessionId }`；出参 `{ started: true }`（异步完成经 `dsh/state` 或既有 update 通道报告）。
- 自动压缩发生时同样推送事件；状态查询入参 `{ sessionId, op: 'status' }`。

### 3.10 搜索 `dsh/session/search`

- 入参 `{ query, cwd?, limit? }`；出参 `{ hits: [{ sessionId, seq, snippet, title? }] }`。
- 成员侧调自身 session-query；未启用搜索（openAt never）时返回 `{ hits: [] , disabled: true}`，宿主按设置面如实呈现。

### 3.11 导出 `dsh/session/export`

- 入参 `{ sessionId }`；出参导出文档字节流（JSON 文档，格式=成员进程现行导出格式）。
- 宿主以成员返回内容直接应答前端下载，不再自行合成。

### 3.12 附件回读 `dsh/attachment/get`

- 入参 `{ attachmentId }`；出参字节与 MIME。
- 取代宿主 `memberAdmittedImages` 临时登记表：图片引用直接指向成员进程附件库；宿主 session.attachment 透传。

### 3.13 自由提问 `dsh/user/question`

- 提问：成员→宿主请求（复用 JSON-RPC 反向调用），载荷 `{ sessionId, question, options[] }`；回答回程 `{ answerId, value }`。
- 能力位 `userQuestions`；未声明时成员不提问，宿主 UI 不挂载问题面板。

### 3.14 provider 配置迁移

- `unstable_listProviders` → `dsh/provider/list`；`unstable_setProvider` → `dsh/provider/set`；能力位 `providers`。语义不变。

## 4. 宿主消费映射（阶段 C 对照表）

| apiproxy 现行特判 | 阶段 C 后 |
| --- | --- |
| `isMemberSessionId` 分支 ×N | 删除；统一经 SessionBackend 分发到协议客户端 |
| `memberHistory` 全量回放合成 | `dsh/session/historyPage` 分页拉取，写入统一读取缝 |
| per-topic seq 表 / 翻译器缓存 | 保留为流式通道内部态，不再承担重放职责 |
| `memberAdmittedImages` 登记表 | 删除；`dsh/attachment/get` 透传 |
| updateQueue / rename / fork 的 "not supported" | 删除；真实实现或按能力位隐藏 |

## 5. 验证锚点（阶段 E 展开）

- 平价夹具：同一任务套件分别跑「进程内主实例」「本机 dsh 成员经 ACP」，规范化后转录一致（覆盖 §3 全部能力的至少一条断言）。
- 第三方降级：mock-acp-server 不声明 `dsh` 能力 → 相关入口不可见且无残留调用。
- 快照：受影响 assembled-web 输出重录；双 SDK 投影同步。
