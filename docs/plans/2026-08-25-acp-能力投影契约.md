# ACP 能力投影契约 —— DeepSeek Harness 经 ACP 完整自封装（阶段 A）

状态：approved-plan / 施工依据。上游决策记录见 [.opencode/plans/acp-full-self-encapsulation.md](../../.opencode/plans/acp-full-self-encapsulation.md)（批准的架构终稿与阶段划分）；本文件是阶段 B/C/D 的逐能力施工契约。

## 0. 不变量与范围

1. 主实例经 apiproxy 暴露的会话域能力，成员进程经 ACP 后全量具备；不设批次。
2. 桥只做机械投影：每个 `dsh/*` 方法对应成员进程内一个既有服务调用，桥内不出现新业务逻辑。
3. 宿主侧（packages/team）对一切 ACP 对端说同一套协议；界面可用性由 initialize 协商的能力位驱动，不允许按「成员类型」分支。
4. 日志权威在成员进程；历史、搜索、导出等日志类操作经协议路由到属主，宿主不镜像日志。

## 1. 能力协商（按 SDK 实测修正）

钉死的 `@agentclientprotocol/sdk` 已原生提供大量面，dsh 扩展只承载真缺口：

- **原生直接用**：`unstable_listProviders/setProvider`（provider 配置）、`unstable_forkSession`（分叉）、`listSessions`（会话列表）、`setSessionMode`、elicitation 通道存在但形状不合（见提问通道）。
- **dsh 扩展传输**：一律走协议原生 `extMethod/extNotification`，方法名 `dsh/<域>/<动作>`。
- **能力声明**：`agentCapabilities._meta.dsh.extensions[]` 列出桥内注册的全部扩展名（initialize 动态生成）；`sessionCapabilities: { list: { setSessionConfigOption }, fork }`。
- 缺失 `_meta.dsh` = 第三方最小实现；宿主据此隐藏入口。

## 2. 通用约定

- **命名**：扩展方法一律 `dsh/<域>/<动作>`，JSON-RPC 参数对象单参。现有 `unstable_listProviders` / `unstable_setProvider` 在本次一并迁移为 `dsh/provider/list` / `dsh/provider/set`（两端都是我们的代码，无兼容负担）。
- **会话标识**：全部方法携带成员自己的 topic `sessionId`（string）。宿主持有的 `member:<memberId>:<topicId>` 虚拟 id 仅在宿主↔前端之间存在，永不跨线。
- **错误**：复用 ACP 层既有错误构造（`invalidParams` / `internalError` / 自定义 code）。业务错误码与 apiproxy 现行码对齐：`session-not-found`、`model-unavailable`、`queue-item-not-found`、`attachment-error` 等；第三方 CLI 未实现某方法时返回标准 JSON-RPC `-32601`，宿主按能力位预先隐藏而非依赖该错误。
- **事件**：异步变更经既有 `session/update` 通知通道携带扩展变体（见 §4 state/compaction），不复用 `config_option_update`。

## 3. 逐能力契约（✅ = 已实现于桥）

### 3.1 模型目录全量化 ✅

- 来源：`ctx.llm.listProviders()` 全路由 × `listModels`，逐路由 best-effort。
- 编码：选项 value 为组合串 `${provider}/${model}`；`changeModel` 对枚举条目**整串匹配**解码（含斜杠 id 安全），同时改写 `modelRef.current.provider/.model` —— 跨 provider 切换生效。
- 广告条件收敛：llm 缝存在且任一路由目录非空即广告；初始 selection 仅决定 currentValue。
- 测试：`packages/acp/acp/tests/config-option.spec.ts`。

### 3.2 会话列表 ✅ 原生 `listSessions`（桥既有）。

### 3.3 历史分页 ✅ `dsh/session/historyPage`

- `{ sessionId, before?, limit }` → `{ events, total, nextBefore? }`；before 为独占 0-based 日志索引，limit 钳制 ≤200。

### 3.4 排队与 steer ✅ `dsh/session/queue`

- `{ sessionId, op: list|enqueue|remove|edit|steer, text?, itemId? }`；直投 live agent inbox，语义同主实例 queue dock。

### 3.5 重发 `dsh/session/rerun`（待实现）

- 主实例语义在成员进程内执行：checkpoint 截断其后日志并以原输入重开回合。依赖 checkpoint 缝摸底后落地。

### 3.6 分叉 ✅ 原生 `unstable_forkSession`

- 整日志 seed 子会话并注册为 live；源不动。协议分叉不带锚点。

### 3.7 改名 ✅ `dsh/session/rename`

- 投影 sessionTitle 服务；title-invalid → 参数错误，其余内部错误（与主实例分类一致）。

### 3.8 会话状态 ✅ `dsh/session/state`

- GET：todo/planMode/goal 三域日志折叠（各自 last-wins）；live 变更已走原生 update 流（todosToPlan 等），无需独立通知。

### 3.9 压缩 ✅ `dsh/session/compact`

- 触发投影 `compaction.compactNow(liveAgent)`。原设计的 status 查询无服务缝支撑，删除。

### 3.10 搜索 ✅ `dsh/session/search`

- `{ query, limit? }` → `{ hits }`；搜索关闭或未挂载 → `{ hits: [], disabled: true }`（数据化缺席）。

### 3.11 导出 `dsh/session/export`（待实现·重活）

- 宿主导出是 apiproxy 自实现（431 行 zip 流水线，含媒体条目与 artifact 收集）。桥侧移植需基于 persistence+attachments 独立组装；先立小设计再动手。

### 3.12 附件回读 ✅ `dsh/attachment/get`

- `{ attachmentId }` → `{ mediaType, bytes, data(base64) }`；替换宿主临时登记表的前提。

### 3.13 提问通道 ✅ `dsh/user/question`（反向 extMethod，非 elicitation）

- 成员进程：桥注册为 user-questions provider，ask() → agent→client `extMethod('dsh/user/question', { questions })`。
- 宿主：team 连接层 Client.extMethod 接收 → `team/user-question` 事件 + 内联应答或 `team.answerUserQuestion(memberId, requestId, answers)`；无订阅者时以空答案集软性谢绝。SDK 会把客户端拒绝包成通用 Internal error（细节仅在 wire data 里）。

### 3.14 provider 配置 ✅ 维持原生 `unstable_listProviders/setProvider`——迁移计划作废（它们是 SDK 原生面）。

- 第三方降级：mock-acp-server 不声明 `dsh` 能力 → 相关入口不可见且无残留调用。
- 快照：受影响 assembled-web 输出重录；双 SDK 投影同步。
