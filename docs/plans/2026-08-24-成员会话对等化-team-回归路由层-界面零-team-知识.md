# 成员会话对等化：team 回归路由层，界面零 team 知识

## 原则（用户定调）
team 是 host 的路由层概念，不是界面层概念。客户端只看到**会话**：所有会话操作（含创建）走 session 面，host 按会话身份/agent token 路由到成员进程。客户端不解析 `member:` 前缀、不拼装成员 id、非 team 表面不调 `team.*`。

## 现状缺陷（已读码确认）
1. `session.create`（api-proxy.ts:2648）只建主实例会话；而 history/models/prompt 等都有 `isMemberSessionId → memberXxx(...)` 路由分支——**创建是唯一没走路由的会话操作**。客户端因此直接调 `api.team.newSession` + 本地拼 id + refresh-retry（workspaces/service.ts:179-231）。
2. Wire `SessionSummary`（sessions.schema.ts:52-62）无 owner 字段，客户端只能 import host 包 `team-sessions.ts` 解析 id 前缀做 scope/分组（ui-workspace 三处 + runtime + ui-team），且按 cwd 把成员话题塞进目录工作区组（tree.ts:224-234）——与"成员是对等 agent、支持无 cwd 会话"矛盾。
3. 新成员话题无标题时显示 UUID；主实例新会话显示"新会话"——不对等。

## Wire 变更（扩展公共 API，需批准）
1. `session.create` payload + `agentId?: string`（不透明 agent token；缺省=主实例）。refine：`agentId` 与 `workspaceId`/`cwd` 互斥。响应不变（`{sessionId}`），host 返回**完整会话 id**。
2. `SessionSummary` 行 + `host/session-added` 帧 + `agentId?: string`（缺省=主实例）——成员话题的行由 host 填，客户端按数据过滤而非解析 id。
3. `team.sessions` 响应项返回**完整会话 id**（host 拼装），不再返回裸 topic id——任何客户端都不再拼 id。

## Host 改动（packages/host/apiproxy）
- `sessions.create`：顶部加路由分支——`agentId` 存在 → 该成员的 bridge（复用现有 team.newSession 原语）→ host 侧 `makeMemberSessionId` 拼装 → 广播行帧（带 agentId、blank）→ 返回完整 id；成员不存在/bridge 失败映射现有 team 错误码。缺省走现主路径不变。
- session.list 成员行 + 新话题的 `host/session-added` 帧：填 `agentId`。
- blank 对等：新成员话题标 `blank: true`，首条 user prompt 经 host 路由时清除（复用主实例 blank 生命周期机制；实施前先核对主路径 clear 点）。→ 新话题行在两种 scope 下都显示"新会话"，UUID 标题消失。
- `team.sessions`：host 侧拼装完整 id。

## Client 改动（删除 team 知识）
- **runtime/workspaces/service.ts**：`startSession` 单一路径——读当前行的 `agentId`；有 → `sessions.create({agentId})` → `sessions.open(返回值)`；无 → 现有 workspace/free 逻辑。删除：`api.team.newSession` 调用、`openMemberTopic`、id 拼装、refresh-retry（若 select 与行帧竞态，在 manager 的 create/select 契约处一处修死，两条臂同规则，不做 per-caller retry）。
- **ui-workspace**（WorkspaceBrowser/tree/Rows）：scope 过滤改读 `summary.agentId`；成员话题无 host workspace 注册 → 自然落 Ungrouped（与 free session 同路），删除 cwd-matching 特判（`memberWorkspaceOf`、tree.ts 成员循环、`sameWorkspacePath` 若无他用则删）；Rows 成员判定改读行数据。
- **ui-team/team-store**：openMember 新话题臂 → `sessions.create({agentId})`；既有话题用 `team.sessions` 返回的完整 id 直接 open；删除本地 `memberSessionId` 拼装与前缀 import。roster 管理（add/remove/start/stop）留在 `team.*`——那是 team 表面，合理。
- 全部客户端包移除对 `@deepseek-ai/dsh-host-apiproxy/src/team-sessions.ts` 的跨层 import；该模块保持 host-only。

## 测试与门
- Host：create+agentId 路由到成员 bridge 并返回完整 id、行帧带 agentId/blank、未知成员错误码、主路径回归（现有 spec）、blank 随首条 prompt 清除。
- Client runtime：startSession 成员臂发 `session.create({agentId})` 且无 team.* 调用。
- ui-workspace：三个成员 spec 改写——按行数据 scope、落 Ungrouped、drag 顺序存 ungrouped 账户。
- ui-team：openMember 两臂（新话题走 session.create；既有话题完整 id）。
- 门：`pnpm run test:gui` → `DSH_SNAPSHOT=replay pnpm run test:web`（组装输出变化）→ typecheck/build。

## 实机验收
client bundle 重建 + 页面刷新；host 路由改动需 dsh 重启。验收流：topbar 点成员 → 侧栏只显示该成员话题（未分组区，无目录嵌套）→ 新建会话 → 新对话打开、行显示"新会话" → 发文本/贴图/取消正常 → 回主实例不受影响；devtools 确认 workspace 表面零 `team.*` 调用。
