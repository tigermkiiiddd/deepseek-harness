# 成员（ACP agent）对等接入计划

## 背景与目标

你指出的问题成立：成员会话此前是"报一个修一个"的补丁式接入，多个 UI 面停在半接入状态——按钮存在但点了必失败（模型选择、重发/分支、图片发送），这不是 ACP 体系的限制，是接入没做完。ACP 本身有完整的对应概念：`session/setSessionConfigOption`（模型选择，dsh ACP bridge 已从 llm catalog 构建 `"model"` 选项并带 provider 路由）、`providers/list|set|disable`、prompt content blocks（含图片，bridge 经 `admitAcpPrompt` 支持）、`requestPermission`（成员侧已实现）。

**目标（验收标准）**：Web GUI 中成员会话是完整的一等会话——每个会话域面要么通过 ACP 真实概念桥接可用，要么在 UI 上对成员显式隐藏并给出原因。不存在"按钮存在但点了必失败"的状态。用 `outline-writer` 成员在 http://127.0.0.1:63848 走通全流程人工验证。

## 工作项（按依赖排序）

### W1 模型选择桥接（host，客户端零改动）
- `api-proxy.ts`：`models`/`selectModel` 加成员分支。
  - `models`：`parseMemberSessionId` → `team.getConfig(memberId, topicId)` → 用 `SessionConfigSnapshot.model` 快捷面合成合法 `SessionModels`：单 group（id `member`、name 取 `team.list()` 的成员 title）、models = 选项值列表、`current = {provider:'member', model: currentValue}`、`routable: true`；成员无 model 选项时返回 `model-unavailable` 响亮失败。
  - `selectModel`：→ `team.setConfig(memberId, topicId, 'model', value)` → 回 `{selected}`；失败映射 `model-unavailable`。
- `TeamServiceShape` 补 `getConfig`/`setConfig`（类型引 `@deepseek-ai/dsh-team/types` 的 `SessionConfigSnapshot`）。
- 测试：`client-handler.spec.ts` 脚本化 team face——合成目录、current 回显、无选项报错、setConfig 透传与失败映射。

### W2 成员图片 prompt（打通真实 ACP 能力）
- `packages/team/team`：`MemberConnection.prompt` 扩展为可携带 content blocks（text + image），`TeamService.prompt` 面同步；ACP `PromptRequest.prompt` 原生支持 `ImageContent`。
- `api-proxy.ts` `memberPrompt`：移除"仅文本"拒绝，把客户端图片 part（base64）转 ACP `ImageContent` 转发；保留大小/类型准入（复用 attachment limits）。
- 验证 dsh ACP bridge 端 `admitAcpPrompt` 对图片的落盘/模型路由行为。
- **模型可见变更**：需按仓库测试政策补 keyless 快照（成员带图 prompt 的回放场景）或说明豁免理由。

### W3 消息动作对等
- **重发**：先读 `ui-conversation/apply.ts:416` 的完整 rerun 流程，确认客户端是否在 `sessions.rerun` resolve 后自行 prompt。成员分支语义 = "把该条用户消息作为新一轮发出"：若客户端随后会 prompt，则 host 成员分支只做确认（no-op accept）；若不会，则由 host 从 `readHistoryEvents` 取原文再 `team.prompt`。实现时以读到的行为为准，二选一写死并测试。
- **分支/fork**：ACP 原语存在但 dsh bridge 未实现——本计划不实现成员 fork（记录为 deferred），改为 UI 对成员会话隐藏"分支"动作（按 session kind 门控，附 locale 原因文案）。

### W4 steer/队列面隐藏
- 成员无 inbox、ACP 无 steer 原语：UI 对成员会话隐藏 steer 与队列编辑入口；host `updateQueue` 加成员守卫返回明确错误码（替换现在的误导性 `queue-item-not-found`），双保险。

### W5 重命名隐藏
- UI 对成员会话隐藏重命名动作（ACP 无原语）；列表显示继续用 `memberSessionDisplayTitle`。

### W6 受限面记录 + 导出隐藏
- 会话搜索不覆盖成员内容、日志导出不支持成员：写入 team/runtime README 的 Known Limitations（ACP 无对应原语，dsh bridge 未实现），UI 对成员隐藏导出动作。搜索框保持全局可用（主实例内容）。

### W7 成员 ask_user 通道
- **先验证**：在 `outline-writer` 上触发一次 ask-user（或读 dsh ACP mode 下 ask-user 工具的解析路径），确认现状是挂死、报错还是静默降级。
- **再修复**：首选把成员的 ask-user 映射到 ACP `requestPermission`（成员侧已有实现，api-proxy.ts:1367 的审批桥已能转发应答）；若工具在 ACP mode 根本无法挂载，则在成员 preset 组合中显式禁用并记录原因。

### W8 验证与收尾
- `pnpm run test:gui` 全绿（两个既有红外——`renderMessageImages`、`web-search-exa` 断言——单独报告，不在本计划内修）。
- `DSH_SNAPSHOT=replay pnpm run test:web`：先查上次崩溃（exit `0xC0000005`，疑似构建 OOM）根因并跑绿。
- 人工验收清单（live GUI + outline-writer）：列表打开成员 → 新建对话 → 发文本 → 贴图发送 → 取消 → 权限应答 → 切换模型 → 重发消息 → 确认分支/steer/重命名入口已隐藏且无失败按钮。
- 一份 Agent Note（`implemented/feature/2026-08-24-web-member-parity-integration`，中英双份 + i18n 配对）：对等接入原则、审计表、逐项决策与 deferred 清单；扩展 [ACP virtual team](.agents/notes/implemented/feature/2026-08-16-acp-virtual-team.md) 与 [ACP member model and provider configuration](.agents/notes/implemented/feature/2026-08-23-acp-member-model-and-provider-config.md)。

## 明确 deferred（记录不实现）
成员 fork、成员内容搜索、providers/* 配置 UI（ACP 有、team service 已封装，留作后续 lane 功能）、成员↔成员消息。

## 假设与风险
- W2 依赖 dsh ACP bridge 图片路径真实可用——实现时以 `admitAcpPrompt` 行为为准；若 bridge 实际不支持，W2 降级为"UI 对成员隐藏贴图入口 + host 保留明确错误"（仍是消除失败按钮）。
- W7 现状未验证，修复形态取决于验证结果（映射 requestPermission vs 显式禁用）。
- 客户端门控遵循 slot/props 纪律：按 session kind（`member:` id 前缀）在 inject 面做可用性判断，不新增公共 API。
